# Dedicated crop model

The default diagnosis provider is `hybrid`: a real, pretrained MobileNetV2
classifier runs on the server CPU before one Gemini image review/report request.
The model was integrated into this application, not trained by this project.

## Model and execution

- Original fine-tune: https://huggingface.co/linkanjarad/mobilenet_v2_1.0_224-plant-disease-identification
- ONNX conversion: https://huggingface.co/onnx-community/mobilenet_v2_1.0_224-plant-disease-identification-ONNX
- Pinned revision: `95110a1ffcc188d1b5a36524d52e303e40c2403d`
- Full float32 weights: 9,227,028 bytes; SHA-256 `c209f96f0a87a265b0ff6765c2e84d48038a7d8b8692d7629445b4513c344eb7`.
- ONNX Runtime CPU; RGB, shortest edge 256, center crop 224, normalization to [-1,1].
- Weights are downloaded and verified during build, packaged in the server
  function, and loaded once per warm process. Visitors do not download the model.
- No Hugging Face inference endpoint, GPU subscription or new paid service is used.
  Existing Vercel and Gemini free-tier quotas still apply; unlimited uptime or
  unlimited reports are not promised.

## Scope and safeguards

The classifier recognizes 38 PlantVillage leaf classes across 14 crops. It does
not cover every disease of those crops, and does not diagnose fruit. Wheat,
mango, rice, cotton and other unsupported crop selections use Gemini and are
explicitly labeled as outside model coverage. Auto-detected crops still require
Gemini to check whether the image is suitable for this leaf classifier.

Gemini independently reviews the image and candidate prediction, then generates
the final diagnosis, treatment, severity estimate and circles. MobileNetV2 is a
classifier, not a lesion detector: the circles are Gemini visual estimates.
Disagreement, missing review, a score below 80, or a top-two margin below 20
triggers a confirmation/expert-review indication. Softmax scores are not accuracy.
Inference failure is recorded as unavailable; the app never claims a model ran
when it did not. Model provenance is server-created, not generated by Gemini.

Standalone diagnosis remains independent of previous reports. My Crops comparison
logic is unchanged. Existing reports remain unchanged until explicitly reanalyzed.

## Verification

`plant-model-benchmark.json` records eight real CPU predictions, with public image
sources and expected labels. Four PlantVillage sanity samples matched; these may
overlap training data. Three of four PlantDoc test samples matched. One healthy
tomato field photo was incorrectly classified as squash with powdery mildew.
This small check is not a representative accuracy estimate or proof of unseen-data
generalization; it is why independent image review is retained.

Local end-to-end classifier processing was 10–78 ms, including preprocessing and
first-load overhead. This is not complete online report latency.

```sh
npm run model:prepare
node --import tsx --test tests/*.test.ts
npm run build
npm run typecheck
```

The benchmark script accepts a JSON array of `{path, expectedLabel, crop, url,
dataset}` and can be run with `node --import tsx scripts/benchmark-plant-model.ts
manifest.json` after downloading the referenced public images.

Set `CROP_DIAGNOSIS_PROVIDER=gemini` and redeploy to opt out of CPU classification.
The separately staged `agrichat` provider requires a working authorized GPU
endpoint; it is not the default and is not being claimed as deployed.
